# Contributing / 贡献指南

Thank you for contributing! Please read the project's README, license, and any repository-specific instructions first. This shared guide is intentionally language- and build-system-neutral.

感谢参与贡献！请先查看对应项目的 README、许可证及项目自身的贡献说明。本指南不预设具体的语言、依赖安装方式或构建命令。

## Before you start / 开始之前

- Check existing issues and pull requests; discuss large changes before implementing them.
- Keep pull requests focused and explain *why* a change is needed.
- Follow the project's existing architecture and coding style, adding tests where practical.
- Run the tests or checks documented in **that project's** README or CI configuration.
- Do not include credentials, private data, third-party material without permission, or unrelated changes.
- Report security vulnerabilities privately as described in [SECURITY.md](SECURITY.md), not in a public issue.

- 先查看已有 Issue 与 PR；大规模调整建议先讨论。
- 尽量保持 PR 小而聚焦，并解释修改动机。
- 遵循具体项目的架构与代码风格，适当补充测试。
- 按**对应项目**文档或 CI 执行检查，不假定所有项目使用同一构建命令。
- 不提交密钥、个人隐私数据、无权授权的第三方代码或无关修改。
- 安全漏洞请依照 [SECURITY.md](SECURITY.md) 私下报告，避免公开披露未修复漏洞。

## License and contribution rights / 许可与贡献权利

Each repository determines its own license. Contributions to that repository are ordinarily made under its stated license and the applicable GitHub terms, unless a separate agreement expressly applies.

每个仓库自行决定许可证。通常，贡献按对应项目已有许可证及适用的 GitHub 条款提交；另有明确协议的除外。

Some projects may **explicitly adopt** the [Lsong CLA](CLA.md) to enable separate commercial relicensing. In those projects, maintainers will request a clear, recorded, affirmative acceptance before merging covered contributions. The CLA is **not** automatically required for every lsongdev project.

部分项目可能会**明确采用** [Lsong CLA](CLA.md)，以支持独立商业授权。对于这些项目，维护者会在合并相关贡献前请求可核实的主动同意；并非所有 lsongdev 项目都强制签署 CLA。

Contributors retain their own copyright. Please make sure you have the right to submit all included material.

贡献者保留其原创代码的版权，提交前请确保拥有必要权利。

## Pull requests / 提交 PR

1. Fork the relevant repository or create a branch as permitted.
2. Make and test a focused change.
3. Explain the motivation, behavior, and testing performed in the pull request.
4. Address review feedback respectfully.

请按照项目文档创建分支，提交聚焦的修改和测试，在 PR 中说明原因、行为变化及验证方式，并友善地回应 Review 意见。

All participants are expected to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
